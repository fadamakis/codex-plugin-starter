# Security

Do not put credentials, personal records, or production integrations in bug reports or sample fixtures.

Report a vulnerability privately through the repository's **Security → Report a vulnerability** flow when available. If private reporting is unavailable, open a minimal issue asking the maintainer for a private contact route; omit exploit details and sensitive data until a private channel is established.

The sample runs a local MCP process and changes only synthetic in-memory notes. Any real service, persistent storage, file access, or additional permission you add needs its own threat and privacy review. Keep dependencies updated and retain their licenses.
